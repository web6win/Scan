## Architecture
- Pure static multi-page frontend, no backend. Node CORS-open; browser talks JSON-RPC batch directly.
- `api.js` block cache (perf-critical, read before changing): immutable blocks fetched once; TTL 4s within 3 blocks of head, 1h deeper; eviction budget 24MB (weighted by tx count). `getBlocksDesc` / `getRecentTransactions` / `getAddressTransactions` / `getValidatorStats` all go through `getBlocksByNumbers()`. New "scan last N blocks" features MUST use this layer; the top new block MUST get short TTL or the home height freezes (regression `_verify2` scenario H).
- 7 pages: index / blocks / tokens / txs / validators / address / deploy. Detail views via hash (`blocks.html#/block/N`, `txs.html#/tx/H`).
- Nav "数据" group order = 区块→通证→交易→验证人 (tokens is its own page `tokens.html`, not a home panel). Desktop dropdown + mobile "数据" panel share `NAV_GROUPS[0].items`. navCount 6, data-route 12 (sync `_pagetest` navCount/tabCount assertions when adding pages).
- Top bar / bottom Tab / footer rendered by `chrome.js` `setupChrome(active, rerender)` — do NOT hardcode nav in HTML (caused "orphan link" drift before). `initI18n()` must run at the start of `setupChrome()` or static `data-i18n` never applies on first paint.
- `config.js` is the single source of truth for chain metadata (UI display + EIP-3085 add-chain params). Change chain only here.
- Modules: api / views / chrome / i18n / utils / wallet (EIP-1193/3085/3326) / network (add-chain UI) / ui (Modal + clipboard) / deploy / abi (ethers v6 wrapper: selector/topic0/ABI codec/proxy detect/ERC20_ABI) / contract (9-tab UI: `viewContract(addr)`).
- `views.js` `viewAddress` checks `acc.isContract` → `import('./contract.js')` → `viewContract(addr)`; EOA takes the original path. Contract changes: ONLY touch `contract.js`, never the EOA branch.
- `assets/vendor/ethers.umd.min.js` (ethers v6.13.4) loaded via classic `<script>` in `address.html` `<head>`, exposes `window.ethers`; `abi.js` uses `getEthers()`. Don't hand-roll keccak / ABI codec.
- Contract "transactions targeting a contract" must NOT only scan recent N blocks: use `api.getContractTransactions()` — (1) `eth_getLogs` via `getLogsChunked` (avoids "range exceeds maximum") to reverse-map all external-call tx hashes that emitted events (covers full history, cheap); (2) scan recent `recentScan`(=800) blocks for event-less / failed txs; merge + dedupe, batch fetch tx+receipt with block timestamps, 10s cache. Old `getContractCalls(addr,limit,maxBlocks)` deprecated (missed early calls by only scanning 2000 blocks).
- Three async renderers (`renderEvents` / `renderTxns` / `renderStorage`) MUST `content.replaceChildren(wrap)` after building `wrap`, else clicking that tab leaves the previous tab on screen.
- `ERC20_ABI` must include the full standard interface (`transfer`/`approve`/`transferFrom`/`allowance` + `Approval` event), else the token Write tab shows 0 cards and Read misses `allowance`.

## Conventions (must follow)
- Code comments in Traditional Chinese (user explicit); zh UI strings in Simplified Chinese. Don't mix.
- First-screen "sync shell first": Hero (h1 + "add to wallet" CTA) must paint BEFORE any `await`; unknown values render `—` / config fallback first, then only mutate text nodes (`#heroHeight` / `#heroMeta`) on data arrival. Measured 4538ms → 216ms.
- Lists / overview = skeleton first paint + in-place update (3s interval + busy guard), never rebuild panels (avoid flicker / hover interrupt). New pages must use the "sync skeleton first" pattern.
- Node-down: do NOT cover the whole page with an error box (kills Hero + add-chain CTA); push the error into the content panel, keep Hero, 3s retry self-heal.
- Mobile nav = bottom Tab (hide top nav ≤560px); Modal = bottom sheet on mobile, centered dialog on desktop.
- Color: compute contrast with `_pickcolor.mjs` before changing (body 4.5:1, large 3.0:1). Use the `-ink` text-color variants for text; fill/border colors (`--accent` #2f6df6 = 4.15:1, `--teal`, `--warn`) are NOT text-safe. `--accent-ink` #1c4fd0 = 6.25:1 is text-safe; same `-ink` pairing extended to `--teal-ink` / `--warn-ink`. New semantic colors: always pair a fill var with a dedicated `-ink` text var; never let a fill var double as text color.
